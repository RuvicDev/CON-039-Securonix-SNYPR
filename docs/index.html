¿Qué es y para qué sirve?

El conector Securonix SNYPR permite que el agente de Ruvic consulte y gestione incidentes de seguridad detectados por la plataforma SIEM/UEBA de Securonix — listar incidentes, ver el detalle completo de uno específico, o actualizar su estado.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Qué incidentes críticos están abiertos ahora mismo?"
  • "Dame el detalle completo del incidente 12345."
  • "Marca el incidente 12345 como cerrado, fue un falso positivo."

Operaciones soportadas:

OperaciónQué hace
siem.list_incidentsLista incidentes, con filtros opcionales (estado, prioridad, fecha)
siem.get_incident_detailConsulta el detalle completo de un incidente puntual
siem.update_incident_statusActualiza el estado de un incidente
Fuera de alcance a propósito Este conector no crea ni elimina incidentes, y no gestiona whitelists, watchlists, ni lookup tables — esas capacidades quedaron fuera de esta versión.

Prerrequisitos

  • Un tenant de Securonix SNYPR (cloud u on-premise) accesible por red desde donde corre Ruvic.
  • Un usuario de servicio dedicado, con acceso al módulo de gestión de incidentes — nunca una cuenta de administrador de la plataforma.
  • Las rutas exactas de la API REST para la versión/instalación específica del tenant — pueden variar entre versiones (6.3, 6.4, cloud vs on-prem).
  • Para pruebas: idealmente un tenant de pruebas separado del productivo — no existe una versión de Securonix descargable para levantar localmente.

Configuración en el fabricante

  1. Pide al administrador de Securonix un usuario de servicio dedicado.

    Debe tener acceso al módulo de gestión de incidentes (lectura, y escritura si se va a usar la actualización de estado), sin permisos administrativos de la plataforma.

  2. Confirma la URL exacta del tenant.

    El formato típico es el hostname o IP de la instalación, a veces incluyendo /snypr al final — confírmalo con el administrador, varía según la instalación.

  3. Confirma las rutas exactas de la API REST de incidentes para esa versión.

    Securonix provee un Postman collection para probar su API — pide al administrador que confirme (o te comparta) las rutas de "listar incidentes", "detalle de incidente" y "actualizar estado" para la versión específica del tenant, ya que han cambiado entre versiones.

  4. Prueba la generación de token desde línea de comandos (opcional pero recomendado). 
curl --request GET \
  --url 'https://TU_TENANT/ws/token/generate' \
  --header 'username: TU_USUARIO' \
  --header 'password: TU_CONTRASEÑA' \
  --header 'validity: 365'

Una respuesta con un token (texto o JSON) confirma que las credenciales funcionan.

Permisos requeridos

PermisoPara qué lo usa el conector
Lectura de incidentesNecesario para list_incidents y get_incident_detail
Actualización de estado de incidentesNecesario solo si se va a usar update_incident_status

No otorgues permisos administrativos de la plataforma, ni acceso a módulos que este conector no usa (whitelists, watchlists, lookup tables, configuración del sistema).

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Securonix SNYPR y pulsa Configurar.

Completa la URL base, el usuario y contraseña del usuario de servicio. Deja los campos avanzados (rutas de API, validez del token) en sus valores por defecto salvo que hayas confirmado que tu tenant usa rutas distintas.

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a [URL del tenant]".

  2. Prueba mínima con el agente.

    Pide algo de solo lectura primero:

    "¿Qué incidentes abiertos hay?"

Solución de problemas

Mensaje / síntomaCausa probable y solución
"No se pudo generar el token..."Usuario o contraseña incorrectos. Verifica con el administrador de Securonix.
"No encontrado" en list_incidents/get_incident_detail (HTTP 404)Lo más probable es que la ruta configurada para ese endpoint no coincida con la de tu tenant — confírmala con el administrador y ajusta el campo avanzado correspondiente, en vez de asumir que no hay datos.
"Permisos insuficientes" (HTTP 403)El usuario de servicio no tiene acceso al módulo de gestión de incidentes, o le falta el permiso de escritura para actualizar estados.
"No se pudo conectar..." (timeout/red)El tenant no es alcanzable desde donde corre Ruvic — puede requerir VPN o whitelist de IP.

Preguntas frecuentes y notas de seguridad

¿El agente puede crear o eliminar incidentes?

No. Esta versión del conector solo lista, consulta detalle, y actualiza el estado de incidentes existentes.

¿Por qué algunas rutas de la API son configurables?

Porque Securonix ha cambiado los nombres de sus endpoints entre versiones (6.3, 6.4, cloud vs on-prem), y no hay una única ruta universal documentada públicamente. Dejarlas configurables evita tener que esperar un cambio de código si tu tenant usa nombres distintos.

¿Dónde queda guardada la contraseña?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarla.

Buenas prácticas Usa siempre un usuario de servicio dedicado, nunca una cuenta administrativa; confirma las rutas de API exactas con el administrador antes de dar por sentado que el conector "no encuentra" algo; y confirma la intención del usuario antes de cambiar el estado de un incidente real.
